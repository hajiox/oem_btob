# OEM運用追加機能（2026-10-01）

## 実装範囲

- 精算中の製造・出荷アラートを「精算保留」として表示（020）。
- 企業・個人識別キーと確認根拠による初回特典の管理、案件ごとの試作番号・結果・監査履歴（021）。初回特典は同一企業キーにつき1案件、試作2回まで。通常の試作費は2回まで10,000円で、案件3回目以降の追加費は3,000円。管理画面の追加費表示は参考値であり、自動請求しない。原料等の実費は正式見積で確認する。
- 試作・ラベル・仕様の内容を固定した顧客承認URL。最新の確認対象が未承認なら製造開始をDBでも拒否。旧版・取消・期限切れURLを無効化し、回答の二重登録を防止。価格変更・正式発注規約同意とは別の機能。
- 未入金・未送信の請求書を同額訂正。既知の送信済み請求書は同額訂正ではなく、未入金なら理由付き取消・同内容再発行。元番号・内容・入金履歴を保持し旧URLは失効。送信中・結果不明・入金後・精算開始後の訂正を禁止（022）。
- 請求書の発行時は入金済み計画・前金未確認・支払期日不一致・不正な税額/振込先を拒否する。回帰検証で検出した022のガード欠落を追加マイグレーション024で復元。訂正履歴はactive判定で分離し、OEM案件スコープを重複返却より先に確認する。
- 完成・出荷記録から納品書、全額確認済みの銀行入出金から領収書を固定生成。精算済み案件では返金を差し引いた確認済み純受領額を使用。発行済み書面はその時点の履歴であり、後の返金を上書きしない。後続の入出金は精算書と台帳で確認する。HTML印刷・PDF保存に対応。
- 会計事務所用CSV：請求書・銀行入金・精算入金・返金を種類別で出力。JSTの開始日〜終了日（含む）、安定ページング、BOM、数式注入保護。請求と入金の二重計上を避ける。テスト案件は明示されるため提出前に除外する。
- 顧客進捗ポータル：期限付き・失効可能なURLで当該案件の仕様、請求書または精算の税込金額、銀行確認状態、製造・配送情報を表示（023）。未発行請求の見積額を確定支払額として扱わない。
- 出荷と全額入金・精算が済んだ案件だけ再注文下書きを作成。元仕様を引き継ぐが価格・承認・規約同意・入金・無料特典は引き継がない。再見積と正式発注が必要。

## 運用上の境界

銀行明細の確認は人が行う。メール送信、銀行操作、支払・返金は自動実行しない。企業同一性は担当者が確認し、同じ識別キーと確認根拠を使う。進捗・承認URLは知っている人が閲覧できるため、案件相手にのみ共有する。これらの画面は検索対象外・キャッシュ禁止で、広告/アクセス計測タグを載せない。

## 検証

テストスクリプトはPGトランザクション内で実行しROLLBACKする。DB制約・トリガーを無効化しない。

- `verify-oem-hold-alerts.cjs`：製造可→精算保留→解除、DBゲート、権限。
- `verify-oem-trials-approvals.cjs`：案件ごとの追加費、会社特典、内容付き冪等性、固定履歴、承認紐付け、旧版・失効、製造ゲート。
- `verify-oem-invoice-revisions-documents.cjs`：税別94,000円（8%）＋6,000円（10%）→税込108,120円、前金54,060円。訂正・再発行、入金、製造予定100→完成105個、出荷、書面、精算返金4,320円→純受領103,800円。
- `verify-oem-portal-reorder.cjs`：権限、期限・失効、別案件遮断、税込残額、再注文条件、選択肢改ざん防止、価格・同意の非継承。
- `verify-oem-accounting-csv.cjs`：日付、式注入、OEMスコープ、実Supabaseの読み取り専用JOIN。
- 既存の見積（94通り）、請求、製造、精算の回帰テスト。
- 024適用後の請求テスト：一部入金後の新規発行拒否、前金なし残金発行拒否、null区分、内訳上限、不正な銀行情報、既存支払計画の期日不一致。入金/製造/精算/新規機能の回帰テストはすべてPASS。

実画面用の `prepare-oem-completion-demo.cjs --commit` は「OEM追加機能テスト・支払不要」の架空案件だけを追加する。実メールは送らず、実取引・実銀行確認の記録ではない。
