# ⑥ 定型文・AI返信案（2026-10-01）

## 操作

管理画面のOEM案件の「顧客メールスレッド」内、「定型文・AI返信案」を展開する。

1. 受付・支給原料・試作・支払・製造・出荷・精算の7種から選び、定型文を準備。
2. 必要な場合だけ、表示された問い合わせ・指示・定型本文・案件情報を確認してGoogle Geminiへの送信をチェックし、AI返信案を作成。
3. 候補を確認し、返信本文に反映。既存本文があれば置換チェックが必要。
4. 編集して下書き保存、または既存の送信前プレビューで宛先・返信対象・本文・添付を確認して送信。

生成・反映だけで保存やメール送信はしない。AIによる条件・金額・数量・日付の正しさを保証せず、担当者が確認する。適用条件、納期、受入可否、味、製造可否の決定をAIに委ねない。

## 参照と保護

- 最新の注文・支払予定・銀行明細確認済み入金、製造数量・記録済み出荷、確定精算を参照。
- 最新未対応受信を専用検索で優先、なければ最新受信。上位50件だけから推定しない。
- ご相談段階のBTO商品・包装・支給等は限定質問から参照。正式発注後の選択変更を確定仕様として扱わない。
- 税別見積と税込請求・入金を区別。取消・精算案件では旧請求を現在の請求としない。返金額は負の請求でなく返金として表示。
- 支払・出荷定型文は工程別。入金済み・出荷済み・取消済みに新たな前金義務を案内しない。
- 旧規約に現行キャンセル条件を自動適用せず、精算下書きを確定額として案内しない。
- 既存サーバー専用`GEMINI_API_KEY`を利用。デフォルト`gemini-2.5-flash`、任意`OEM_REPLY_AI_MODEL`。キーはブラウザに渡さない。
- Googleへ送るのは確認した問い合わせ・指示・宛名なし定型文・限定案件情報。社内配合・原価・問題メモ、添付、認証情報、保存済み下書きは送らない。
- 既知の氏名・会社・メール・URL・電話・識別子等を伏せるが、匿名化は完全保証できない。担当者が送信内容を確認する。
- JSON・文字数・数値・URLを検証。不明数値・リンク・機密情報らしい出力を拒否する。意味や約束の正しさは人が判断する。
- 管理者・同一サイトOrigin・OEM案件範囲、24KB入力上限、厳密な操作フィールドを検証。
- 担当者1時間20回まで。安定UUIDと不変台帳により同じ生成でGoogleを再呼出ししない。通信不明時は同じIDで結果確認、pending/failedに自動再要求しない。
- 適用直前は案件・受信・共有下書き全体を検証。下書きには事実ハッシュを保持し、再読み込み・編集後も保存/送信時に案件・入金・受信の変更を再検証。
- 下書き保存は更新時刻による競合拒否。同じ担当者・件名・本文・参照情報のみ冪等。共有下書き再読み込みは未保存編集の置換チェック後に行う。
- 既存の二段階送信確認・安定送信ID・不明結果自動再送禁止を維持。
- 事実変更による送信前拒否は`not_sent`として返す。Gmail未実行を送信結果不明と混同せず、再準備できる。

## DB・検証

SQL019：生成台帳（RLS、service_roleは参照と限定RPCのみ）、下書き参照列、生成claim/finalize、競合防止draft RPC。既存注文・入金・精算の書換えなし。

- `verify-oem-reply-ai.cjs`：外部APIモック、JSON/上限/数値/リンク拒否。
- `verify-oem-reply-assist.cjs`：同意、変更、重複台帳、Origin/権限/案件/過剰指定。
- `verify-oem-reply-draft.cjs`：古い事実ハッシュで保存・送信しない。
- `verify-oem-reply-templates.cjs`：匿名化、仕様質問の選別、定型文、2種類のハッシュ。
- `verify-oem-reply-assist-db.cjs --with-migration`：BEGIN/ROLLBACKでRLS/権限/同一ID/レート/不変台帳/下書き競合。
- 既存conversation-security / reply-snapshot / mail-sync / mail-attention回帰。実メール送信なし。
- 旧`verify-oem-conversations-db.cjs`はSQL012を無条件に作る設計のため適用済みDBでは既存テーブルエラーとなる。今回はSQL019/016のDB検証と既存送信オフライン検証で確認。既存テーブル削除・再作成なし。

`npm run build`、変更対象ESLint、`git diff --check`を実行。

## 実画面検証

`scripts/prepare-oem-reply-demo.cjs`の「返信案動作テスト・支払不要」、`reply-assist-demo@example.invalid`のみを使用。架空受信を登録して定型文・AI案・反映・保存・再読込を確認。実注文・銀行操作・顧客メール送信なし。

画面確認は既存の通常Chrome連携。リモートデバッグ・PC操作を先に使わない。

本番画面で7定型文を準備し、原料支給定型文の反映・保存、Gemini実生成1回・既存本文置換・保存を確認。DBで生成ready1、保存本文236文字・事実ハッシュあり、架空受信1、送信0・発注0を照合。証跡：`output/reply-assist/01-ai-draft-saved.png`、`02-ai-candidate.png`。SQL019適用済み、初回実装コミット`6c4ae49`はVercel READY・独自ドメインaliasを確認。

公式API資料：https://ai.google.dev/api/generate-content 、https://ai.google.dev/gemini-api/docs/text-generation
