## 不具合・修正優先項目

### 1. メールアドレスの検証が不十分【実画面再現】
会社名と氏名を入力しメールを `a@` とすると、送信ボタンが有効になる。ボタンはform外で直接handleSubmitを呼び、HTMLのemail検証を通らない。サーバーにも形式検証なし。送信自体は未実施。
参照: src/components/InteractiveForm.tsx:248, 382, 768 / src/actions/publicForm.ts:113。

### 2. 金額・回答のサーバー側再検証がない【コード確認】
申込側から渡された estimatedTotalPrice と selectedOptions をそのまま保存し、メールへ使用する。商品・選択肢・価格・送料の正当性をDBから再計算していない。ブラウザからの改変を拒否する実装が必要。本番への改変送信は実施していない。
参照: src/actions/publicForm.ts:113-153。

### 3. メールHTMLに自由入力をそのまま埋め込む【コード確認】
会社名・担当者名・備考等にHTMLエスケープがない。タグを文字として扱わず、メール本文やレイアウトへ影響させる可能性がある。メールクライアントでのスクリプト実行を確認したものではない。
参照: src/actions/publicForm.ts:200, 207, 209, 229。

### 4. 送信中の例外から復帰する処理がない【コード確認】
submitLeadが例外になった場合のcatch/finallyがなく、送信中状態の解除とエラー案内が行われない。通信断等を本番で故意に起こす試験は未実施。
参照: src/components/InteractiveForm.tsx:346-385。

### 5. 販売価格シミュレーションの1円丸め誤差【実画面再現】
リーズナブル＋バルクのカレーは商品単価350円。利益率30%の計算は350÷0.7=500円だが、表示は501円。浮動小数点誤差のある値をMath.ceilしている。OEM見積総額146,000円は正しい。
参照: src/components/InteractiveForm.tsx:677。

### 6. 未完成の価格が「現在のお見積り」として表示される【実画面確認】
お茶を選んだ直後、プラン未選択なのに6,000円（送料だけ）が表示される。カレーなども材料・包装選択前は78,000円（製造手数料＋送料）になる。完成見積と誤認しやすいため、選択完了までは「仕様選択中」等にする。
参照: src/components/InteractiveForm.tsx:220-225, 477付近。

## 改善提案（仕様判断が必要）

1. 結果画面に商品・味の方向・容器・原料有無と原料名の確認一覧を追加。現状は価格内訳中心で、原料名や希望する味が確認しづらい。
2. 瓶詰めは「ジャムかご飯のお供か」、ラーメンは「こってりの中の鶏白湯か豚骨か」など、価格に影響しない希望が伝わりにくい。選択肢を増やすより、申込時の任意欄「作りたい商品・味のイメージ」で補う。
3. 「この内容で仮申込する」は実際には連絡先入力画面へ進むだけ。「この内容で相談する」＋「まだ送信されません」に変えると行動と文言が一致する。
4. スマホは結果カードの余白と条件説明が長く、相談ボタンが下方にある。文字を縮めず、余白を削減し、詳細説明を整理する。送料ラベルの不自然な改行も調整。
5. 商品単価とは別に「送料込み参考原価」を補足すると採算判断しやすい。400個商品なら1個あたり+15円、茶バルク100袋なら1袋あたり+60円。既存の送料等別単価を置換するかは別途判断。
