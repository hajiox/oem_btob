# OEM進捗ポータル／再注文下書き

## 運用境界

- 管理者が明示的に専用リンクを発行・失効・更新する。発行時は32バイト乱数のBearerを一度だけ画面へ返し、DBにはSHA-256ハッシュだけを保存する。メール送信は行わない。
- リンクは最大90日、期限・失効を毎回サーバー側で検証する。公開投影は会社名、発注番号・工程、現在の合意額／精算状態、銀行入金確認額、数量・日付・配送情報、正式仕様だけで、内部メモ・原価・レシピ・メール・担当者・認証情報は返さない。
- 精算が存在する間は旧発注の未払い額を表示せず、精算合意額と精算反映後の残額だけを表示する。見積額は「正式見積額（未確定）」と明示する。
- 顧客からの再注文は、発送済みかつ税込請求額の完済、または発送済みかつ精算完了（精算ブロックなし）の場合のみ、UUIDのリクエスト台帳で冪等登録する。元発注の承認・入金・特典・価格有効期限は複製しない。新規leadは金額0の`negotiating`下書きで、正式UIで再見積り・再合意する。

## 適用と検証

1. `sql/023_oem_portal_reorder.sql`を既存の001〜022の後に適用する（請求書lifecycle_statusに依存）。
2. `src/lib/oem-portal.test.ts`はBearer長・ハッシュ、期限上限、再注文CTAの状態境界を検証する。
3. 顧客ページは`/btob/progress/[token]`。管理側の`OemPortalPanel`は上位のOEM案件パネルから明示的に配置する（自動メールなし）。
