# OEM受付・案件管理（2026-09-19）

## 追加した機能
- OEM受付のみ、DBトランザクションで問い合わせと2通のメール待ち記録を保存。
- 同一内容の再試行を冪等化。ブラウザには個人情報を保存せず、ハッシュ・UUID・作成時刻のみ24時間保持。
- IP／メールごとに1時間5件の固定窓制限。匿名からOEM leadを直接INSERTする経路を閉鎖。その他LPの受付経路は維持。
- メール状態と手動再試行。`sent`はResend受付済であり配達確認ではない。結果不明は同じキーで再試行し、23時間経過後は重複送信防止のため調査待ち。
- 案件検索・ページ送り・全件SQL集計。メール要確認・次回フォロー日を一覧に表示。
- 社内メモ、原料状態、試作、配合、作業時間、出来高、課題、最終仕様、手動の顧客承認根拠／日付。
- DBトリガーで変更前後の履歴を保存。仕様変更時は古い承認を解除。同時編集はupdated_at比較で拒否。
- 公開フォームの名称を「会社名・農園名・屋号」に変更。

## 適用と検証
`scripts/oem-db-migrate.cjs`はファイル指定・チェックサム記録・トランザクション方式。008〜010を先行適用し、アプリ公開後に011のOEM直接INSERT制限を適用する。

検証: `npm run build`、`verify-oem-security.cjs`（94有効経路）、`verify-oem-operations.cjs`、`verify-oem-mail.cjs`、`verify-oem-db.cjs`。
DBテストはロールバックし、実メールは送らない。DBテストに1,005件の集計・匿名拒否・旧LP互換・メールclaim排他・重複受付・制限・履歴・承認解除を含む。

## 運用上の注意
- 自動再送スケジューラー、受信箱到達の保証、休日カレンダー連動は追加していない。管理者が一覧で要確認・期限を確認する。
- 既存案件の過去のメール状態は推定しない。「導入前のため記録なし」と表示。
- 顧客承認はメール等を受けた後の社内記録であり、顧客の電子署名機能ではない。
- 既存LPビルダー、料金、商品選択フローは変更しない。
