# OEM手動入金管理（第1段階）

## 方針

- 銀行API・会計ソフトは使用せず、管理者が銀行明細で確認して記録する。
- 管理画面上部に全OEM案件の前金/残金待ち、期限超過、請求予定未設定、過入金を表示。
- 税別見積額から税額を推測せず、実際の請求額（税込）を手動設定する。正式な請求書/税区分・前金控除は後段で整備する。
- 入金日・金額・名義・メモ・確認管理者を保存。分割入金を合算し、請求額と完全一致した場合のみ工程を進める。
- 支払期限は未設定も許容。未設定のまま期限超過と推定しない。期限超過は日本時間の当日と比較する。
- 旧「入金済みにする」だけの操作は廃止。サーバーとDBでも入金記録なしの進行を拒否。
- 過入金は要確認として残す。返金・訂正は後段の機能であり、本段階で帳尻合わせの請求額変更は行わない。
- 入金記録は追記式。更新/削除不可。二重送信IDは同一内容の再試行に再利用する。

## 実演

`scripts/prepare-oem-payment-demo.cjs` は `DEMO-PAYMENT-20260929` のみを再利用または作成する。
会社名に「動作テスト・実取引なし」を明示。メールは送信せず、銀行にも接続しない。
accepted状態は合成テスト用初期状態であり、お客様による規約同意の証拠ではない。

## 検証

- 第1段階の変更ファイルのESLint、TypeScript、production build。
- `node scripts/verify-oem-payments.cjs --with-migration`（DB変更もデータもROLLBACK）。
- migration適用後に既存正式発注テストと入金テストを再実行。
- 本番Chromeで請求予定登録→一部入金→残額入金の画面テスト。証跡は別途保存。
- 全体lintは既存ファイル/生成済みoutputに99エラー・10警告。無関係なコードは変更しない。
