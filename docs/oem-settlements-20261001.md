# ⑤変更・キャンセル精算（2026-10-01）

## 運用

- 管理画面の正式発注欄に「精算管理」を追加。規約同意前は従来の発注取下げ、同意後のキャンセルは精算の下書き・合意確認を経て確定する。
- キャンセルの対象額は合意済みキャンセル料・実費の総額。既存規約の資材手配前30,000円／手配後実費を参考表示し、個別条件・税区分は担当者が確認する。自動課税・自動請求はしない。
- 金額調整は製造後（残金待ち・全額入金済み・出荷済み）の、発注全体の最終合意額。製造前のレシピ・仕様変更を自動承認する機能ではない。
- 8%税抜対象、10%税抜対象、非課税・不課税を入力し、税率ごとの円未満切捨てで税込総額を算出。
- 差額＝今回の合意総額－（元の入金＋精算受領－精算返金）。正は追加受領、負は返金、ゼロは精算完了。
- メール等の合意根拠を保存し、管理者が顧客との合意を確認して確定。顧客が新規規約へ同意したという証拠を代行作成するものではない。
- 銀行への送金・返金・メール送信は自動実行しない。手動で銀行確認後、日付・金額・名義・確認メモを記録する。部分入出金可。

## 保護

- 元の正式見積・請求書・入金を上書きしない。確定済み精算・入出金証跡を削除／改変できない。
- 未確定下書き／未処理差額は製造・発送を保留。精算を開始した発注では元の前金・残金管理を閲覧専用にし、既存請求書の顧客URLも停止。管理者は原請求履歴を注意表示付きで確認可能。
- 合意額・受領額スナップショット、操作者・変更前後を監査履歴に残す。
- 各操作にrequest UUIDを持ち、同じ内容の再試行は重複登録しない。別内容で同一IDを使うと拒否。注文ロック＋楽観versionで競合を防ぐ。
- 下書き取下げと完了後の精算改訂に対応。旧改訂の完了状態は後続入出金で再計算しない。
- キャンセル済みでも元の発注・支払履歴を表示。合意後キャンセルの精算未完了時は改訂発注を止める。
- 管理画面上部に下書き・追加請求・返金・期限超過・旧キャンセル精算未設定のアラート。通常案件を誤って精算未設定にしない。

## 書類・制限

- 管理者認証付き `/admin/settlements/[id]` に印刷・PDF保存用の精算確認書（控え）。顧客公開URLや自動送付は追加していない。
- 履歴は直近50改訂／100入出金を表示し、超過時は省略を明示。アラートは50件単位。
- 新DB環境では既存008〜017に加えて018を順に適用。018は追加テーブルと既存状態制御・アラートの拡張で、既存業務レコードの削除・更新は行わない。
- 検証は `verify-oem-settlement-boundaries.cjs`（オフライン）、`verify-oem-settlements.cjs --with-migration`（ロールバック）、既存注文／入金／請求／製造テスト、TypeScript・ESLint・build。
- 架空デモは `prepare-oem-settlement-demo.cjs --commit`。example.invalid宛て、支払不要・実銀行入出金なしの2案件に限定し、既存デモをリセットしない。
