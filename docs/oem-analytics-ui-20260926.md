# OEMアクセス解析UIの簡素化（2026-09-26）

- 国内向けOEM LPで、訪問時のアクセス解析同意ダイアログとフッターの設定ボタンを廃止。
- OEM LPではGA4を通常読み込みし、商品選択・概算表示・相談開始・送信完了を計測する。
- 氏名、連絡先、相談内容、任意の検索語や未承認のURLパラメータは送信しない既存制約を維持。
- Google広告・Meta広告は未導入。Googleの広告用ストレージ、広告ユーザーデータ、パーソナライズ信号は拒否状態を維持。

## 社内・テストアクセスの除外（2026-10-04）

- `utm_campaign=oem_tracking_test` のアクセスでは、OEM用Googleタグ・ページ表示・商品選択・概算・相談イベントを送信しない。テストURLを開くだけで恒久的な除外登録はしない。
- 社内確認に使用するブラウザーは、本番の `/analytics-settings` で「このブラウザーを集計から除外」を押して登録する。`oem_analytics_internal_v1=1` をlocalStorageに保存し、OEM LPのみ計測を抑止する。「通常の集計に戻す」で解除できる。
- 登録はブラウザー・プロファイル・端末ごと。通常のお客様には設定画面やバナーを追加せず、従来の計測とフォーム処理を維持する。保存機能が使えない場合は設定画面に失敗を表示する。
- GA4のInternal TrafficフィルタはIPルール未確認のためTESTのまま維持する。本対応は送信前の除外であり、既存の集計データを削除しない。過去の `oem_tracking_test` はレポートのキャンペーン条件で別扱いにする。
- Analytics用Membrane接続は本人によるGoogle再認証後にREADYへ復旧。読み取り専用のまま、OEMプロパティ555029617の集計取得をHTTP 200で確認した。
- 組み込みRun ReportアクションはbaseUri不足のエラーを返したため、CLIの認証済みproxyで `https://analyticsdata.googleapis.com/v1beta/properties/555029617:runReport` を明示して取得する。認証情報は手動で取り出さない。
- 検証: Analyticsユニットテスト9件・変更した4つのTypeScript/TSXファイルのESLint・型確認・Next.js本番ビルドが成功。全体の `npm run lint` は既存スクリプトや未変更ソースにある152エラー・17警告で失敗しており、本変更とは分けて扱う。
- 本番では除外登録・再読込後の保持・解除・再登録、登録済みブラウザーおよび未登録ブラウザーのテストURLでGoogleタグが読み込まれないことを確認した。社内IPの一括除外は未設定であり、別ブラウザーでは上記設定画面から個別登録する。
- 設定画面は既存のグローバルresetによるTailwind余白の上書きを避けるため、画面内限定のCSS Moduleを使用する。公開LPのCSSは変更しない。
